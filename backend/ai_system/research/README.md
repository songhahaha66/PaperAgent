# Research sessions

The main Agent reads materials, computes in independent Python processes with disk-backed job receipts, answers in the conversation and edits the manuscript directly through `writing.edit`. Delivery validates current files/references and renders/exports them; there is no separate section-writing Agent or model repair pipeline. Compiler diagnostics return to the same research conversation.

Direct Python steps use the existing manifest run receipts (`runs.py`), never claim/commit experiments or manufacture an acceptance verdict. A question ID is optional metadata; unknown explicit IDs fail without borrowing another question. `research.create_question` accepts no ID, while `research.edit_question` requires the returned short ID and current version. Research topics are optional grouping metadata, with no registered answer or completeness status. The old question-splitting and experiment interpretation operations remain internal compatibility interfaces for historical records.

`session.py` retains main and delegated message histories on stable threads in the existing graph SQLite database, independently of the outer scheduler's checkpoints. Recovery reconciles tool receipts and saved runs before continuing a pending call. It never assumes Python memory survived, or silently replays submitted code.

`graph/compaction.py` keeps the original project instructions and recent complete tool rounds, replaces old completed code with immutable source paths, offloads large outputs to readable files and summarizes completed history at the model context boundary. Summaries are fallible working notes cached in existing command records; source messages, current question state and run archives remain authoritative. Each request records estimated message/tool context size separately from actual provider usage.

`research.delegate` creates an isolated work directory and a persistent child conversation. Isolated tasks receive the task and selected files; forked tasks also receive the parent's current messages. Children cannot delegate or edit the main manuscript. Follow-ups reuse task IDs; changed input files require a new task. Generated outputs use the existing immutable run publisher. All requests, including summaries and children, share ResearchRuntime. Up to two child calls may run concurrently; jobs in a shared workspace remain serialized.

ResearchStore owns current questions, requirements and versions; manifests own actual direct run receipts and files; LangGraph checkpoints own conversation position. File transfer retries preserve run identity. User amendments in new direct sessions return to the same Agent without an extra experiment-planning model. Domain checks remain calculation code and semantic review stays advisory. Historical registration references and old document edits remain readable.

Legacy acceptance verdicts and review findings do not gate scheduling, writing or delivery. Dependencies use execution completion and current input versions. Recoverable tool errors retain a failed action receipt and return to the Agent with their diagnostic; they are not replayed automatically on resume. Budget exhaustion, repeated failures and uncertain external execution still require a safe stop or explicit recovery.

Offline evals inspect actual published files instead of registered number strings. `python -m evals.microgrid <source.xlsx> <result1.xlsx>` checks the supplied microgrid Q1 against an independent LP and daily energy balance with explicitly documented efficiency/timing assumptions. It is a task-specific evaluation, not a production acceptance gate or a verifier for Q2–4.

Methods are loaded on demand through `research.list_skills` / `research.read_skill`. Model comparison is a skill executed by the same Agent with `research.run_python`; dedicated comparison scheduling, candidate generation and handoff are retired. Historical comparison readers remain isolated in `modules/experiments/legacy_comparisons.py`. The UI research tab, answer panel and answer-based counts are removed. Migration 12 preserves old answers as history and removes their fields from current topics.
